## Описание проекта

Проект представляет собой серверное приложение для оптимизации и управления рабочими процессами выездных специалистов, разработанное в рамках кейса №5.

### Стек технологий

- Язык программирования: Kotlin 2.1 (JVM 21)
- Фреймворк: Spring Boot 4.1.2 (Spring MVC, Spring Data JPA, Spring Security)
- СУБД: PostgreSQL 16
- Миграции базы данных: Flyway
- Аутентификация: JSON Web Tokens (JJWT 0.12.6)
- Документация API: SpringDoc OpenAPI 3.2.0 (Swagger UI)
- Сборка и управление зависимостями: Gradle 9.8.2
- Контейнеризация: Docker, Docker Compose

---

## Архитектура развертывания

Сервис разворачивается в виде изолированного стека контейнеров с использованием Docker Compose:

1. **bbsk-postgres** — контейнер реляционной базы данных PostgreSQL 16 (образ `postgres:16-alpine`), обеспечивающий хранение бизнес-данных и автоматическое применение миграций схемы `app`.
2. **bbsk-backend** — контейнер серверного приложения Spring Boot (многоэтапная сборка на базе Eclipse Temurin 21), взаимодействующий с базой данных внутри изолированной сети `bbsk-network`.

## Системные требования

Для запуска проекта в контейнерах:
- Docker Engine версии 24.0 или выше.
- Docker Compose версии 2.20 или выше (в составе Docker Desktop или плагина `docker-compose-plugin`).

Для сборки и запуска без контейнеризации (локальная разработка):
- Java Development Kit (JDK) версии 21.
- Установленный и запущенный экземпляр PostgreSQL версии 14 или выше.

## Конфигурация окружения

Конфигурация сервисов выполняется через переменные окружения. Шаблон параметров представлен в файле `.env.example`.

### Основные переменные

| Переменная | Описание | Значение по умолчанию |
| :--- | :--- | :--- |
| `POSTGRES_SERVER` | Хост для подключения к СУБД (при локальном запуске) | `localhost` |
| `POSTGRES_PORT` | Порт подключения к СУБД на хост-машине | `5432` |
| `POSTGRES_DB` | Наименование базы данных | `rostelecom` |
| `POSTGRES_USER` | Пользователь базы данных | `postgres` |
| `POSTGRES_PASSWORD` | Пароль пользователя базы данных | `postgres` |
| `POSTGRES_SCHEMA` | Рабочая схема базы данных | `app` |
| `SERVER_PORT` | Внешний порт HTTP-сервера | `8080` |
| `SECRET_KEY` | Ключ для формирования подписи JWT-токенов | Генерируется автоматически при отсутствии |

> При запуске через Docker Compose контейнер приложения автоматически подключается к сервису `postgres` по внутренней сети, поэтому значение `POSTGRES_SERVER` внутри compose-сети задано как `postgres`.

## Инструкция по запуску в Docker Compose

### 1. Подготовка конфигурационного файла

Создайте файл `.env` на основе шаблона `.env.example`:

- **Linux / macOS:**
  ```bash
  cp .env.example .env
  ```

- **Windows (PowerShell):**
  ```powershell
  Copy-Item .env.example .env
  ```

При необходимости отредактируйте параметры в файле `.env`.

### 2. Сборка образов и запуск сервисов

Выполните команду сборки и фонового запуска всех сервисов:

```bash
docker compose up -d --build
```

*(В случае использования устаревшего синтаксиса допускается вызов `docker-compose up -d --build`)*

Процесс запуска включает:
1. Запуск контейнера СУБД `bbsk-postgres`.
2. Прохождение healthcheck-проверки готовности базы данных (`pg_isready`).
3. Многоэтапную компиляцию приложения и создание оптимизированного JRE-образа.
4. Запуск контейнера приложения `bbsk-backend`.
5. Автоматическое применение миграций базы данных Flyway при старте приложения.

### 3. Мониторинг состояния и просмотр логов

Проверка статуса запущенных контейнеров:

```bash
docker compose ps
```

Просмотр потока логов всех сервисов в реальном времени:

```bash
docker compose logs -f
```

Просмотр логов исключительно серверного приложения:

```bash
docker compose logs -f backend
```

Просмотр логов базы данных:

```bash
docker compose logs -f postgres
```

### 4. Остановка сервисов

Остановка и удаление контейнеров и общей сети:

```bash
docker compose down
```

Остановка с полным удалением томов с сохраненными данными базы данных:

```bash
docker compose down -v
```

## Проверка работоспособности сервиса

После успешного запуска приложение доступно по базовому адресу `http://localhost:8080`.

### 1. Проверка состояния (Healthcheck)

- **Метод:** `GET`
- **URL:** `http://localhost:8080/api/v1/health`
- **Пример ответа:**
  ```json
  {
    "status": "ok",
    "team": "Бубышки",
    "version": "1.0.0"
  }
  ```

### 2. Интерактивная документация API (Swagger UI)

Интерфейс Swagger UI для тестирования и просмотра спецификации эндпоинтов доступен по следующим адресам:

- **Swagger UI:** `http://localhost:8080/swagger-ui.html` (или `http://localhost:8080/swagger-ui/index.html`)
- **Спецификация OpenAPI (JSON):** `http://localhost:8080/v3/api-docs`

### 3. Эндпоинты аутентификации

- Регистрация пользователя: `POST /auth/register` (или `/api/auth/register`)
- Авторизация пользователя: `POST /auth/login` (или `/api/auth/login`)

## Локальный запуск без контейнеризации приложения

Данный режим предназначен для разработки и отладки бизнес-логики без постоянной пересборки Docker-образа.

### 1. Запуск только СУБД PostgreSQL

Запустите контейнер базы данных:

```bash
docker compose up -d postgres
```

База данных станет доступна по адресу `localhost:5432`.

### 2. Запуск приложения Spring Boot через Gradle Wrapper

Перейдите в директорию `back` и запустите приложение:

- **Linux / macOS:**
  ```bash
  cd back
  ./gradlew bootRun
  ```

- **Windows (PowerShell / CMD):**
  ```powershell
  cd back
  .\gradlew.bat bootRun
  ```

Приложение подключится к запущенной в Docker базе данных PostgreSQL и применит необходимые миграции схемы.
